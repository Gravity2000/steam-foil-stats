# Steam 补充包闪卡统计

统计 Steam 补充包和挂卡掉落开出闪卡的**实际概率**。

网上关于闪卡掉率的说法一直没有定论，掉率逻辑跑在 Valve 服务器上，客户端拿不到。
唯一能接近答案的办法是统计——这个脚本自动扫描你的库存历史，
把每一次开包、每一次掉卡的结果记下来，算出观测掉率和置信区间。

## 使用

1. 打开 <https://steamcommunity.com/my/inventoryhistory/>
2. 页面顶部会出现统计面板
3. 填好要统计的数量，点「应用」
4. 点「开始扫描」，脚本自动翻页抓取，每页间隔 4 秒
5. 扫描期间**保持页面打开**（可以切到其他标签页）
6. 之后再次扫描会自动增量更新，连续 3 页没有新数据就停

### 两个数字决定一切

```
补充包 [    ] 包  ·  挂卡掉落 [    ] 张卡   [应用]
```

规则只有一条：**填数字就统计这么多，留空或 0 就完全不管这一类**。

| 想看什么 | 补充包 | 挂卡掉落 |
|---|---|---|
| 只看开包出闪率 | `500` | 留空 |
| 只看挂卡出闪率 | 留空 | `1000` |
| 两个都看、顺便对比 | `500` | `1000` |

被设为 0 的那一类不扫描、不显示、不进日志、不进 CSV，完全当它不存在。

单位不同是有原因的：补充包固定一包 3 张，「包」是自然单位；
挂卡的记录会把同一时段的多次掉落合并成一条（一条里可能有 1~2 张卡），
按条数算会低估三成左右，所以用**卡牌张数**。

**想扫全部就填个大数**（比如 `9999`），扫到库存历史末尾会自动停。

设置在扫描过程中也能改，点「应用」立即生效，不用停下重来。

## 结果怎么看

### 三个指标

| 指标 | 算法 | 说明 |
|---|---|---|
| **补充包 · 单卡出闪率** | 闪卡张数 ÷ 卡牌总数 | 一包 3 张卡 = 3 次机会，分母用卡牌数 |
| **挂卡掉落 · 单卡出闪率** | 闪卡张数 ÷ 卡牌总数 | 同上，分母是张数不是记录条数 |
| **补充包 · 单包含闪率** | 含闪卡的包数 ÷ 总包数 | 用来反推机制，见下 |

两个渠道都开时，面板会自动判断**差异是否显著**（两边样本都超过 100 张卡后生效）：
置信区间不重叠就是显著差异，重叠则说明数据支持「两个渠道掉率相同」。

### 单卡率和单包率的关系能反推机制

- 若**每张卡独立判定**，单包含闪率应该 ≈ 1-(1-p)³ ≈ 3 倍单卡率
- 若**按包判定后再决定给哪张卡**，两者的关系会不同

这正是社区争议的点之一，有足够样本时可以用数据说话。

### 置信区间比百分比重要

样本小的时候，观测到的百分比几乎没有意义。

300 张卡里出 3 张闪卡，观测值 1%，但 95% 置信区间大约是 **0.3% ~ 2.9%** ——
真实值是 0.5% 还是 2.5%，这份数据都无法排除。

样本量和区间宽度的关系（观测率 1% 时）：

| 卡牌数 | 约等于包数 | 95% 区间 |
|---|---|---|
| 300 | 100 | 0.3% ~ 2.9% |
| 1,500 | 500 | 0.6% ~ 2.0% |
| 6,000 | 2,000 | 0.8% ~ 1.3% |
| 15,000 | 5,000 | 0.9% ~ 1.2% |

想验证「单卡出闪率到底是不是 1%」，大概需要一万张卡以上。
每款游戏每天只能做一个包，所以这是个**长期项目**，先把管道跑起来慢慢攒。

> 顺带一提：如果你连开一百包没出闪卡，别急着怀疑人品。
> 假设真实掉率是每包 1%，连续 100 包不中的概率约 **36.6%** ——
> 三个人各开一百包，大概就有一个和你一样。每包判定独立，没有保底，
> 前面连续多少包不中都不会提高下一包的概率。

## 关于隐私和安全

这个脚本：

- **只读**库存历史页面，不发起任何交易、不修改库存、不动任何物品
- **不上传任何数据**，所有统计结果存在浏览器本地（`GM_setValue`）
- **不需要账号密码**，用的是你浏览器里已登录的会话
- 代码全部公开在本仓库，可以自己审

导出的 CSV 也是在你本地生成的，没有服务端参与。

## 已知限制

**Steam 库存历史只保留有限时间**（通常几个月）。更早的记录已经查不到，
无论怎么翻页都拿不回来。第一次扫描能抓到多少就是多少，之后靠增量积累。

**翻页太快会被限流**（HTTP 429），脚本会自动等 60 秒重试。默认每页间隔 4 秒，
不建议改小。

**Steam 改版会导致解析失效。** 脚本依赖库存历史页面的 DOM 结构，
如果 Valve 改了页面，需要更新选择器。遇到扫描不出数据请提 issue。

## 解析规则

统计的事件：

- 补充包：事件描述含 `已拆开补充包` / `Unpacked booster pack`
- 挂卡掉落：事件描述含 `因游戏时数而获取` 等

**明确排除的**：市场购买、宝石购买、交易、礼物兑换。
这些记录里同样会出现闪卡，混进来会把掉率算高——这是最容易出错的地方。

其他细节：

- 闪卡判定：卡牌名称含 `(闪亮)` 或 `(Foil)`
- 去重靠每条记录的 `history<hash>` ID，重复扫描不会重复计数
- 中英文界面都支持，切换语言不影响统计
- 按游戏分组时，游戏名从补充包名称去掉「补充包」后缀得到
